# Hybrid Search Core

> La degradación controlada de Hybrid se detalla en [Hybrid Search Graceful Degradation](hybrid-search-graceful-degradation.md).

Hybrid Search combina resultados léxicos y semánticos sin modificar sus motores. Ejecuta lexical independientemente de semantic y, cuando hay exactamente un `IEmbeddingGenerator`, genera la query para consultar `ISemanticSearchEngine` con el mismo presupuesto de candidatos. No genera ni persiste conocimiento y no construye contexto. Memory durable no vuelve durable Vector Index ni embeddings; el mantenimiento incremental de esa proyección es eventual y no altera esta frontera.

Los resultados se fusionan por `MemoryItemId`; un resultado semántico sin esa referencia conserva como identidad su `VectorRecordId`. El score es la suma ponderada de score léxico normalizado y score semántico, con pesos normalizados para permitir configuración no unitaria. El orden es score híbrido descendente, score semántico descendente, score léxico descendente e ID ascendente.

Hybrid exige un único provider explícito para la rama semantic. Con cero o varios generators no escoge uno de forma implícita: semantic queda no disponible, pero lexical puede devolver `PartialSuccess` con resultados. Si una fuente falla y la otra tiene resultados, devuelve `PartialSuccess` y warnings seguros; si ambas fallan devuelve `Failed`. El estado `Dirty` no bloquea todavía semantic retrieval; representa que sus resultados pueden ser stale y la rama lexical durable conserva su degradación habitual. Una rama sana sin hits conserva la puntuación híbrida normal; una rama caída renormaliza la sana a peso efectivo `1.0`. La cancelación prevalece. Sus referencias las consume Context Builder mediante `IMemoryStore`; RAG Pipeline las usa después mediante contratos, sin que Hybrid Search construya prompts, llame al modelo o exponga endpoint o Tool.
